# AeriScope 高级研究前端设计

## 目标

在现有长春 PM2.5 SNN 项目上增加高级中文研究驾驶舱。数据处理、窗口构造、统计、PR 曲线、案例选择与模型训练继续全部由 Python 完成；浏览器只负责展示、筛选和实验参数提交。

## 技术方案

采用 FastAPI + React/TypeScript/Vite。选择这一方案是因为现有项目已是 Python 包，FastAPI 可直接复用数据与流水线；React 适合多视图交互，Recharts 提供可访问的响应式图表，Lucide 提供统一图标。不引入 CloudBase、Next.js 或独立数据库，避免与研究目标无关的部署复杂度。

## 视觉系统

产品名 `AeriScope · 澄空`。深海军蓝侧栏、暖白工作区、青绿主色、珊瑚色预警色，配细边框、轻阴影、紧凑数据字体和克制的卡片圆角。桌面为固定侧栏与多列分析网格，移动端折叠导航并单列展示。支持明暗主题、键盘焦点、跳转正文、语义表格、表单标签和减少动态效果偏好。

## 视图

1. **研究总览**：来源与运行状态、最佳 PR-AUC、SNN 召回/误报率、测试样本、模型横向对照、污染月度趋势、关键结论和研究边界。
2. **数据洞察**：缺失率、月度/采暖季、PM2.5 时间序列、气象滞后关联、事件统计。
3. **模型对照**：四模型 PR 曲线、指标切换、验证/测试指标表、阈值与混淆矩阵。
4. **SNN 实验室**：直接时间编码示意、网络参数、模拟步数、各层脉冲率、训练/推理开销及非节能声明。
5. **误差案例**：成功预警、漏报、误报切换，预测起点与未来窗口标注，真实案例缺失时明确空状态。
6. **运行实验**：空气/气象 CSV 路径、窗口、提前量、阈值、训练轮数、SNN 步数；后台运行、状态轮询、失败原因和完成后刷新。

## API

- `GET /api/health`：服务状态。
- `GET /api/dashboard`：配置、数据覆盖、分区、指标和月度摘要。
- `GET /api/eda`：缺失、季节、滞后、事件统计及下采样序列。
- `GET /api/models`：四模型指标和 Python 计算的 PR 曲线。
- `GET /api/cases?model=snn`：Python 选取的 TP/FN/FP 上下文序列。
- `GET /api/report`：Markdown 报告下载。
- `GET/POST /api/experiments`：当前状态与启动实验；单任务后台执行，禁止并发覆盖。

API 默认读取 `artifacts/demo`，新实验写入 `artifacts/web-runs/<run-id>`。CSV 路径必须位于项目目录内，运行 ID 使用 UUID。前端开发服务器通过代理访问 FastAPI；生产模式由 FastAPI 托管 `frontend/dist` 和生成图表。

## 数据契约与异常

所有响应显式携带 `data_source`。缺失产物返回明确 503/404，不返回伪数据。API 错误使用 JSON `detail`，界面提供可重试错误状态。加载使用骨架或状态文本；图表同时提供标题、说明和关键数值，不仅依赖颜色。

## 验证

- Python 编译与 API 真实请求：状态、字段、来源、PR 曲线和三类案例。
- npm 生产构建与 TypeScript 检查。
- 内置浏览器端到端：六个视图、模型指标切换、误差案例切换、主题切换、移动布局。
- 通过界面启动一次合成实验，观察状态完成并验证新产物。
- 检查浏览器控制台、横向溢出、键盘焦点及网络错误。
