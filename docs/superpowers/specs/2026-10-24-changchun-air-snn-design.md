# 长春空气污染 SNN 预警项目设计

## 1. 目标与边界

依据根目录《方案三_长春空气污染_SNN预警.md》创建一个可运行、可复现的 Python 研究项目。核心是短期 PM2.5 事件预警及公平模型比较，而非搭建实际公共预警系统。统计关联不解释为因果；普通计算机运行时间与脉冲数量不解释为硬件节能。

默认实验使用过去 48 小时预测未来 6 小时内 PM2.5 是否达到 75 μg/m³。该阈值是预先固定的研究事件定义，不宣称等同于官方小时级预警标准。采暖季默认定义为 10 月至次年 4 月，仅作为分析分组。

## 2. 方案选择

采用配置驱动的命令行流水线，代码按数据、特征、数据集、模型、训练评估、可视化和报告拆分。

未采用 Notebook 优先方案，因为模块与命令行更利于固定配置、重复执行和检查泄漏；未采用 Web 仪表盘，因为它会增加与研究目标无关的前端和部署工作。

## 3. 项目结构

- `pyproject.toml`、`requirements.txt`：Python 3.11+ 与依赖。
- `configs/default.yaml`：窗口、阈值、时间划分、模型与随机种子。
- `src/changchun_air/`：可安装包及命令行入口。
- `data/raw/`：用户提供的真实数据；不提交私人或大型数据。
- `data/demo/`：明确标注的合成演示数据。
- `artifacts/`：清洗数据、配置快照、指标、模型、图表和报告。
- `README.md`：安装、数据格式、真实数据流程及演示命令。

## 4. 数据设计

统一使用小时时间戳和 `Asia/Shanghai` 本地时间语义。空气质量 CSV 支持常见中英文列名，至少包含时间与 PM2.5，其他污染物可选。气象数据包含温度、相对湿度、风速、风向、气压和降水中的可用字段。

提供 Open-Meteo Historical Weather API 下载器，保存原始 CSV 和请求元数据。空气质量平台当前无法直接自动下载，因此不绕过访问限制；用户从数据源合法下载后放入 `data/raw/`。

提供固定随机种子的合成数据生成器，仅用于端到端功能演示。合成数据包含季节、日周期、自相关污染过程和气象协变量，并在所有结果中标注 `synthetic`。

清洗流程执行字段标准化、数值范围检查、重复时间戳审计、精确小时对齐和缺失统计。不使用双向插值。模型窗口要求目标及特征完整；允许配置仅向前的短缺口填充，但默认关闭。输出清洗日志、缺失率和连续缺失长度统计。

## 5. 特征与无泄漏样本

滚动均值、滚动最大值和变化率只使用当前及过去数据。周期时间采用正余弦编码，风向转换为正余弦分量。

以 `t` 为预测起点，输入 `[t-L+1, t]`，目标为未来 `[t+1, t+h]` 的最大 PM2.5 是否达到阈值。输入窗口与标签窗口都必须连续、完整且不跨数据缺口。

先按预测起点排序划分训练、验证和测试，再在边界清除可能与另一分区重叠的窗口。标准化器仅在训练集拟合。重叠窗口不打乱划分；训练批次可打乱，验证和测试保持时间顺序。

默认按时间比例 60%/20%/20% 划分，并要求每个分区同时存在正负样本；不满足时给出明确错误而非合成或复制测试事件。

## 6. 模型与公平比较

1. 持续性：当前 PM2.5 是否达到阈值，输出 0/1 分数。
2. 逻辑回归：使用当前值、滞后、滚动统计和气象等人工特征，采用类别权重。
3. LSTM：与 SNN 使用相同标准化序列、划分和训练轮数。
4. SNN：snnTorch LIF 神经元、替代梯度、全连接隐藏层；默认直接时间编码，将每个输入向量重复到固定模拟时间步。输入窗口长度和模拟步数分别配置。

深度模型使用固定随机种子、类别加权的二分类损失，保存验证集 PR-AUC 最优检查点。决策阈值只依据验证集 F1 选择，再固定用于测试集。记录参数量、训练时间、测试推理时间和硬件信息；SNN 额外记录各层平均脉冲发放率。

## 7. 评估与图表

输出 PR-AUC、ROC-AUC、Precision、Recall、F1、False Alarm Rate、Accuracy、混淆矩阵、阈值和事件支持数。准确率仅作辅助。保存验证与测试预测明细，便于固定结果重绘。

自动生成至少六类图：数据质量与清洗统计、月度/采暖季污染对比、典型污染过程、多污染物相关及气象滞后关联、模型 PR 曲线、不同模型指标对比、成功预警/漏报/误报案例、SNN 模拟步数与脉冲率/开销关系（具备相应实验结果时）。

默认一次完整运行完成单窗口、单阈值对照，避免事后挑选最优定义。提前量、阈值和 SNN 时间步敏感性作为显式独立配置运行，不在默认流程中自动搜索后汇报最优结果。

## 8. 命令与产物

提供 `demo-data`、`download-weather`、`run` 和 `report` 命令。`run` 依次完成清洗、探索分析、样本构造、模型训练、评估、绘图和报告；各阶段保存配置快照和机器可读 JSON/CSV。

报告区分真实与合成数据，列出数据覆盖、事件定义、划分、模型结果、典型案例和局限性。结果不可复现、样本不足或依赖缺失时明确失败，不生成虚假成功结论。

## 9. 验证策略

项目原先无测试体系，因此不新增测试脚手架。交付前使用 Python 3.11 环境执行：

- 包安装、模块编译和 CLI 帮助检查。
- 固定种子合成数据的完整 `run` 流程。
- 检查四个模型的指标、预测、图表、配置和报告均实际生成。
- 独立冒烟断言：时间窗口连续、标签只取未来、边界无重叠、标准化仅拟合训练集、指标数量与有限值合理。
- 真实 Open-Meteo 小日期范围下载及字段检查；真实空气质量流程因尚无用户 CSV，仅验证导入接口并明确说明未做真实结论验证。

## 10. 完成标准

用户能在 README 指引下安装项目、运行演示、导入真实数据并得到同构产物。完整演示端到端成功，四个模型使用相同样本公平比较，报告不夸大数据来源、预测意义或能耗结论。
